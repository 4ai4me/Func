## 2. 1차시: 함수의 뜻과 그래프 (`Lesson1View`)

교과서 지문 및 시각 자료를 바탕으로 6단계 인터랙티브 탐구 활동지를 제공합니다. 모든 서술형·단답형 입력칸은 학습자가 스스로 생각하여 작성할 수 있도록 내부 예시 문구(`placeholder`)를 비워두었으며, 필요한 경우에만 외부의 **`💡 힌트 보기`** 토글 버튼을 눌러 단계별 가이드를 확인할 수 있습니다.

1. **1단계 — 대응과 함수 (`[생각 열기]` · `[보기]` · `[문제 1]`)**:
   - **인터랙티브 화살표 대응 다이어그램**: 집합 $X$(대한민국, 독일, 프랑스, 미국)의 원소와 집합 $Y$(원, 유로, 달러, 파운드)의 원소를 클릭하여 직접 화살표로 연결하고 함수 여부를 판정합니다 (`💡 생각 열기 힌트 보기` 지원).
   - **`[문제 1]` 함수 판별 활동지**: 세 대응 관계 (1), (2), (3) 중 함수를 찾고, 정의역·공역·치역을 구하며 함수가 아닌 이유(원소 누락 또는 중복 대응)를 스스로 서술합니다.
2. **2단계 — 정의역과 치역 (`[보기]` · `[문제 2]`)**:
   - 정의역이 명시되지 않은 함수에서 함숫값이 정의되는 실수 전체의 집합을 탐구하며, 일차함수 $y=2x+1$과 이차함수 $y=-x^2+3$의 **그래프 힌트**를 토글로 확인하고 정의역·치역을 직접 구해 검증합니다.
3. **3단계 — 서로 같은 함수 (`[탐구+ 문제 3]`)**:
   - 정의역 $\{-1, 0, 1\}$에서 두 함수 $f(x)=|2x|$와 $g(x)=2x^2$의 함숫값 표를 완성하고, 함수의 식이 달라도 정의역의 모든 원소에서 함숫값이 같으면 서로 같은 함수($f=g$)가 됨을 확인합니다.
4. **4단계 — 함수의 그래프 (`[문제 4]` · `[문제 5]`)**:

## 4. 3차시: 합성함수 탐구 (`Lesson3View`)

교과서 지문 및 시각 자료(`[생각 열기]`, `[문제 1]`, `[예제 1 → 문제]`, `[문제 2]`, `[생각 넓히기]`)를 바탕으로 4단계 인터랙티브 탐구 활동지를 제공합니다. 모든 입력칸은 예시 문구(`placeholder`) 없이 비워져 있으며 외부 **`💡 힌트 보기`** 토글 버튼으로 가이드를 제공합니다.

1. **1단계 — 생각 열기 · 합성함수의 뜻 (`01 생각 열기 · 합성함수의 뜻`)**:
   - **인터랙티브 2단 연결 화살표 시뮬레이터 ($X \xrightarrow{f} Y \xrightarrow{g} Z$)**: 세 학생 `X = {아람, 재영, 하영}`을 클릭하여 주문한 음식 `Y = {어묵, 핫도그, 떡볶이, 김밥}`을 거쳐 음식 가격 `Z = {2000원, 3000원, 4000원}`으로 이어지는 2단계 대응 경로를 시각적으로 추적합니다.
   - **합성함수의 정의 및 기호**: $g \circ f : X \to Z$, $(g \circ f)(x) = g(f(x))$의 정의와 **적용 순서($f$ 먼저, $g$ 나중)**를 확인하고 활동지를 작성합니다.
2. **2단계 — 문제 1 · 합성함수의 함숫값 구하기 (`02 [문제 1]`)**:
   - **안쪽 함수부터 2단계 계산 파이프라인 시뮬레이터**: $f(x)=2x+1, g(x)=x^2-1$에 대하여 입력값 $a$와 합성 종류(`g∘f`, `f∘g`, `f∘f`, `g∘g`)를 선택하면 1단계 안쪽 함숫값과 2단계 바깥쪽 함숫값이 순서대로 계산되는 과정을 보여줍니다.
   - **`[문제 1]` 2단계 풀이**: (1) $(g \circ f)(2) = g(f(2)) = g(5) = 24$, (2) $(f \circ g)(-1) = f(g(-1)) = f(0) = 1$, (3) $(f \circ f)(-3) = f(f(-3)) = f(-5) = -9$를 안쪽 함숫값부터 단계별로 구합니다.
3. **3단계 — 문제 · 합성함수 식과 교환법칙 (`03 [문제 (교환법칙)] & [문제 2]`)**:
   - **합성함수 대입 치환 & 교환법칙 비교 실험실**: 두 함수의 대입 과정과 $x$값에 따른 $(g \circ f)(x)$ vs $(f \circ g)(x)$ 결과를 실시간으로 비교합니다.
   - **`[문제 (교환법칙 탐구)]` (교과서 예제 1 문제화)**: $f(x)=-x+2, g(x)=4x+1$에 대하여 (1) $(g \circ f)(x) = -4x+9$, (2) $(f \circ g)(x) = -4x+1$을 스스로 구하고, 일반적으로 $g \circ f \neq f \circ g$ (교환법칙 불성립)임을 확인합니다. (원본 교과서 이미지는 스포일러 방지를 위해 토글 버튼으로 제공)
   - **`[문제 2]`**: $f(x)=x-4, g(x)=-x^2$에 대하여 (1) $(g \circ f)(x) = -(x-4)^2 = -x^2+8x-16$, (2) $(f \circ g)(x) = -x^2-4$, (3) $(g \circ g)(x) = -x^4$를 구합니다.
4. **4단계 — 생각 넓히기 · 합성함수의 결합법칙 (`04 [생각 넓히기] · 문제해결·추론`)**:
   - **3단 함수 합성 파이프라인 시뮬레이터 ($h \to g \to f$)**: $f(x)=2x-1, g(x)=3x+2, h(x)=x^2+1$에 대하여 입력값 $x$가 $((f \circ g) \circ h)(x)$와 $(f \circ (g \circ h))(x)$ 두 결합 경로를 거칠 때 결과가 항상 일치함을 실험합니다.
   - **좌변·우변 식 유도 및 결합법칙 탐구**: $(f \circ g)(x)=6x+3 \Rightarrow ((f \circ g) \circ h)(x)=6x^2+9$와 $(g \circ h)(x)=3x^2+5 \Rightarrow (f \circ (g \circ h))(x)=6x^2+9$를 각각 구해 비교하고, 함수의 합성에서 결합법칙 $(f \circ g) \circ h = f \circ (g \circ h)$가 성립함을 서술합니다.

4. **y = (ax + b)/(cx + d) 변형**: 예제 2를 문제로 `y = □/(x − □) + □` 틀과 점근선 입력(교과서 풀이는 버튼) → 문제 6 (1)(2) + 변형 방법 서술. 각각 그래프 확인, [연습장]
5. **성찰**: 도움 받은 정도 + 성찰 2칸(성찰 1, 10자 이상이 완료 조건)

- **그래프 (`src/components/RationalGraph.tsx`)**: y = k/(x − p) + q를 점근선 양쪽 두 갈래로 나눠 그림(점근선을 가로지르는 선 없음), 점근선 점선·점 표시. `RationalGraphReveal`은 4차시와 같은 규칙(정답 확인을 통과해야 켜짐, 답을 고치면 다시 잠김, 열림 상태는 저장 안 함)

### 5.1 Firestore 저장 구조·보안 (2026-10-30 갱신)

> `Func`와 `Props`는 **같은 Firebase 프로젝트·같은 Firestore 데이터베이스**(`ai-studio-526dd59d-…`)와 **같은 보안 규칙**(`firestore.rules`)을 공유합니다. 규칙을 바꿀 때는 두 저장소의 `firestore.rules`를 똑같이 맞추고, Firebase 콘솔에서 한 번만 게시합니다.

**학생 인증 — Firebase 익명 로그인**
- 학생은 접속 시 자동으로 익명 로그인되며(비밀번호 없음), 가입 문서에 본인 익명 계정 `uid`가 기록됩니다.
- 다른 기기·브라우저에서 로그인하면 이름·생년월일을 **보안 규칙(서버)이 확인**한 뒤 그 기기로 연결합니다(이전 기기 연결은 해제).
- 학생이 [나가기]를 누르면 익명 계정도 로그아웃되어, 공용 기기의 다음 사용자가 이전 학생 문서에 접근할 수 없습니다.
- Firebase 콘솔 → Authentication → 로그인 방법에서 **익명** 제공업체가 사용 설정되어 있어야 합니다.

**차시별 분리 저장**
```text
student_registrations/{studentKey}                 가입 정보·승인 상태·uid
                                                    (+ 예전 worksheetJson: 보존용, 더 이상 갱신하지 않음)
student_registrations/{studentKey}/func_lessons/l1~l7   차시별 답안 (승인된 학생 본인만 쓰기)
                                                    표시 차시 1~8 ↔ 저장 칸: l1 l2 l3 l4 l4 l5 l6 l7 (4·5차시는 l4 공용)
app_settings/func_lesson_access                     Func 전용 차시 잠금 l1~l8 (교사만 쓰기)
student_registrations/{studentKey}/func_lessons/teacher 교사 평가·메모 (교사만 쓰기, 학생은 읽기만)
```
- 학생이 입력을 멈추고 **10초** 뒤, **내용이 바뀐 차시 문서만** 저장합니다. 탭을 닫거나 다른 창으로 전환하면 즉시 저장합니다.
- 차시 문서가 아직 없는 차시는 예전 `worksheetJson` 내용을 그대로 사용하므로 별도 데이터 이전 작업이 필요 없습니다(학생이 그 차시를 수정할 때 자연스럽게 옮겨짐).
- 서버 내용을 불러오기 전에는 자동 저장하지 않습니다(오래된 내용으로 서버를 덮어쓰지 않기 위해). 입력 내용은 그동안 기기(`localStorage`)에 보관됩니다.
- **즉시 저장 시점 (2026-10-30 추가)**: 입력을 멈추고 10초 뒤 자동 저장에 더해, **다음 단계·이전 단계·단계 탭·다른 차시로 이동할 때**, 탭을 전환하거나 닫을 때, 인터넷이 다시 연결될 때 바로 저장합니다(바뀐 차시가 없으면 저장하지 않음). 모든 저장은 `App.tsx`의 `saveNow()` 한 곳에서 순서대로 실행됩니다.
- **저장 실패 대비**: 실패하면 30초마다 자동 재시도하고 한 번 안내합니다. 저장되지 않은 내용이 있을 때 창을 닫으려 하면 브라우저 확인 창이 뜹니다(iPad Safari 등 일부 브라우저는 표시하지 않음). 로그아웃 시 마지막 저장을 최대 5초 기다리고, 저장이 확인되지 않으면 기기에 보관합니다.
- **기기 보관(localStorage)은 학생별**: 학생 모드에서는 `STORAGE_KEY_STUDENT::{studentKey}`에 보관하고, 로그인할 때 **같은 학생의 보관본만** 합칩니다(공용 기기에서 앞 학생 답안이 뒤 학생 문서에 섞이지 않도록). 로그아웃 시 서버 저장이 확인되면 보관본을 지우고 화면을 비웁니다. (`src/utils/studentDraft.ts`)
- 교사 평가·메모는 입력을 **1.5초** 모았다가 `teacher` 문서에만 저장합니다.
- 차시 문서에는 `schemaVersion`(현재 1)이 기록됩니다. 문서 구조를 바꿀 때는 버전을 올리고 읽는 쪽에서 버전별로 처리합니다.
- 관련 코드: `src/utils/lessonStore.ts`(저장·불러오기), `src/utils/lessonMerge.ts`(합치기·변경 감지, 단위 테스트 `lessonMerge.test.ts`).

**학생 비밀번호 (2026-10-30 추가, 기본: 사용 안 함)**
- 교사가 [학생 가입 관리] → **학생 비밀번호 사용** 스위치로 켜고 끕니다 (`app_settings/student_auth.passwordRequired`, Func·Props 공통). 문서가 없으면 '사용 안 함'.
- 켜면: 새 가입은 비밀번호 필수(대문자·소문자·숫자·특수문자 포함 8~32자) / 비밀번호가 없는 기존 학생은 다음 로그인 때 **비밀번호를 먼저 설정해야 활동지가 열림** / 비밀번호를 설정한 학생은 다른 기기에서 로그인할 때 비밀번호 필요.
- 끄더라도 이미 비밀번호를 설정한 학생은 보안을 위해 계속 비밀번호가 필요합니다(필요하면 학생별 초기화).
- **교사 초기화**: 학생 가입 관리 표의 [비밀번호] 열 → [초기화]. 학생은 다음 로그인 때 이름·생년월일로 입장한 뒤 새 비밀번호를 설정합니다.
- 비밀번호 원문은 저장하지 않고 `SHA-256(접두어|학생키|비밀번호)` 해시만 가입 문서의 `passwordHash`에 저장합니다. 다른 기기 재연결 시 `해시:임의값` 증명(`claimPasswordHash`)을 보내고 보안 규칙이 해시를 비교합니다(임의값이 매번 바뀌어 예전 증명 재사용 불가).
- ⚠️ 해시 방식(`src/utils/passwordCore.ts`)은 Func·Props에서 반드시 같아야 합니다 — `passwordCore.test.ts`의 고정값 테스트가 검사합니다.
- 한계: 비밀번호를 아직 설정하지 않은 학생은 이름·생년월일만 아는 사람이 먼저 로그인해 비밀번호를 설정할 수 있습니다. 비밀번호 사용을 켠 직후에는 학생들이 바로 설정하도록 안내하세요.
